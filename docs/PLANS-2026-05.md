## 2. Security — additions

- **2.A Per-user identity.** All non-admins log in as `shared_user`. There
  is no audit attribution. Add a small `users` table with bcrypt hashes
  and a username column; keep `admin_password` env var as a bootstrap.
- **2.B Bound the brute-force backoff dicts.** `_fail_counts` /
  `_last_fail` in `auth.py` grow unbounded per-IP. Cap to N most-recent
  entries (small LRU) so a scanner cannot push memory.
- **2.C Escape `HTTPException.detail` in `http_exception_handler`.**
  It is currently rendered into HTML directly. Use Jinja escaping or a
  template.
- **2.D Settings page warns on `SECRET_KEY`.** Editing it in the modal
  invalidates every session and silently logs everyone out. Add a banner
  next to the field, or remove it from the editable list and require a
  CLI rotation.
- **2.E `.env` writer must quote.** `_write_env_values()` writes raw
  values with no quoting; values containing `=`, `\n`, `#`, or quotes
  silently corrupt the file. Use `python-dotenv`'s `set_key`, or quote
  values that need it.

## 3. Reliability & lifecycle

- **3.1 FastAPI lifespan.** `main.py` uses deprecated
  `@app.on_event("startup")` / `@app.on_event("shutdown")`. Move to an
  `asynccontextmanager` lifespan. While there:
  - Move `BackgroundScheduler.start()` and the `atexit.register` out of
    `config.py` import time (currently a side effect on `import config`).
  - Move logging setup out of module top-level into a single
    `logging.config.dictConfig` call.
- **3.2 Event-driven SSE.** `sse_list` and `sse_stream_health` poll the
  event-bus version every 200 ms. Replace with `asyncio.Event` per
  channel, set via `loop.call_soon_threadsafe(event.set)` from
  APScheduler/FFmpeg threads. Lower CPU and instant updates.
- **3.3 FFmpeg subprocess hardening.**
  - Spawn with `start_new_session=True` so `os.killpg(pid, SIGTERM)` can
    clean up any FFmpeg-spawned children.
  - Drop hard-coded `/usr/bin/ffmpeg`; use `"ffmpeg"` (PATH) or
    `shutil.which("ffmpeg")` so dev on macOS / non-Debian images works.
  - Add a 2 s startup probe; if FFmpeg already exited, surface stderr in
    the toast and DB instead of a bare exit code.
  - Make `name` purely display; use a stable internal `uuid4` for dict
    keys, log filenames, and DOM ids so duplicate names cannot clobber
    `_active_processes`.
- **3.4 Snapshot tmp file race.** `snapshot_field_image()` uses fixed
  `output + ".tmp"`. Use `tempfile.NamedTemporaryFile(dir=...)` for a
  per-call random suffix.
- **3.5 PID recycling check.** `cleanup_stale_streams()` uses
  `os.kill(pid, 0)`. Cross-check the cmdline (`/proc/<pid>/cmdline` or
  `psutil.Process(pid).name() == "ffmpeg"`) before declaring a stream
  dead — defensive, cheap.
- **3.6 Settings save reload UX.** `save_settings()` "touches this file
  so uvicorn's file watcher triggers a reload" — only works under
  `--reload` (dev). In production the change persists but the process
  does not pick it up until restart. Either: (a) make Save explicit
  ("will apply on next restart"), (b) implement in-process re-read of
  `.env` via a `get_settings()` accessor, or (c) signal PID 1 / a
  supervisor.

## 4. Database

- **4.1 Session context manager + indexes.** Combines plan 04 §4.1 with:
  add indexes on `active_streams.status` and
  `active_streams.start_time`. Both are touched on every list request.
- **4.2 Alembic.** Replace ad-hoc inline migrations with Alembic so
  schema changes are versioned and reversible.
- **4.3 Don't let admin delete a `running` row.** `delete_stream_by_id`
  currently allows deletion regardless of status. Block when status is
  `running`, or at minimum log loudly.
- **4.4 Add column lengths.** `Column(String)` is fine for SQLite but
  fails on Postgres if we ever migrate. Specify lengths now while it's
  cheap.

## 5. Code quality / structure

- **5.1 Split `routes.py` (≈32 KB).** It mixes HTTP handlers, SSE
  generators, fragment HTML helpers, the detection cache + threads, and
  the `.env` editor. Suggested layout:
  - `routes/list.py` — list page, remove/cancel
  - `routes/schedule.py` — add/submit
  - `routes/sse.py` — SSE generators (driven by §3.2)
  - `routes/admin.py` — settings, history delete
  - `routes/media.py` — `field.jpg`, thumb, detection
  - `routes/_html.py` — fragment renderers, toast helper
  - This also breaks the `routes ↔ auth` circular dependency that
    forces the `from . import routes` inside `auth.py`.
- **5.2 Move helpers out of `routes.py`.** `_format_bitrate_short`,
  `_format_elapsed_of_total`, `_uptime_text`, `_cpu_temp` belong in a
  small `formatting.py` (and become trivially unit-testable).
- **5.3 Detection cache → APScheduler interval job.** Replace the ad-hoc
  thread + lock + double-spawn pattern with a 60 s interval job that
  writes the cache. Same outcome, half the code.
- **5.4 `RTMP_BASES` dict is built at import time** from `settings`, so
  changes via the admin UI never apply. Build at call time inside
  `_build_output_url`.
- **5.5 `os.makedirs("logs")` is CWD-relative.** Use
  `_PROJECT_ROOT / "logs"` from config.
- **5.6 `random_names.py` cleanups.**
  - `"umpire"` is lowercase among capitalized verbs.
  - Multi-word mascots (`"Mr. Met"`, `"The Phillie Phanatic"`,
    `"Lou Seal"`) break the `Name_Verb` convention used in DOM ids and
    log filenames.

### 6.2 Upgrade plan

1. Bump `datastar-py>=1.0.0` in `pyproject.toml`; `uv lock` and re-test.
2. Replace the local `static/datastar.js` with the v1.0.0 bundle from
   `https://cdn.jsdelivr.net/gh/starfederation/datastar@1.0.0/bundles/datastar.js`.
3. Update the CDN `<script>` tag to `@1.0.0` (or, per plan 04 §6.2,
   switch to `<script type="module" src="/static/datastar.js"></script>`).
4. Verify on a feature branch:
   - SSE list / stream-health endpoints still keep their connections
     open. RC.7 default behavior was already "auto-cancel on element
     removal"; RC.8 changed semantics so cancel-on-removal is opt-in via
     `cleanup` (we never opted out, so this is actually safer for SSE).
   - Form submits (`/submit`, `/cancel_stream`, `/remove_job`,
     `/delete_history`) still work — `data-on:click="@post(..., {contentType:'form'})"`.
   - Modals (`$showScheduleModal` etc.) still toggle.
5. After the upgrade lands, follow plan 04 §6.2 and stop loading any
   Datastar/Bootstrap from CDN — we ship in-the-field over flaky links.

There are **no breaking attribute-syntax changes** between RC.6 and 1.0.0
(the `data-foo-bar` → `data-foo:bar` change happened pre-RC.7 and our
templates already use the new syntax).

Backward-compat note we should sanity-check after upgrade:

- **`retryMaxWaitMs` was renamed to `retryMaxWait`** in 1.0.0. We do not
  use it, so no action needed; flagged for awareness.
- **The `Content-Type: application/json` header is now only set on
  requests with a body.** Should not affect us (we send `form` or rely
  on GET).
- **Backend actions default to peeking signals** (RC.7+). Means
  `@get(...)` / `@post(...)` no longer create reactive subscriptions,
  which matches our usage.

### 6.3 Cleanup opportunities now possible with 1.0.0

These either replace bespoke JS we have today, or simplify verbose
templates:

- **`data-bind` on form inputs.** `_add_form_body.html.j2` manually
  mirrors inputs into signals via `data-on:input="$addStartTime = el.value"`,
  `data-on:change="$addDurH = +el.value"`, etc. Replace with
  `data-bind:add-start-time` and friends. Cleaner, two-way, less code.
- **`data-bind` `__prop` and `__event` modifiers (new in 1.0.0).**
  Useful when a field needs to bind via a non-default property or
  triggered by non-default events. Likely overkill for fieldcam today.
- **`data-computed` for derived signals.** The "Ends at HH:MM" inline
  IIFE in the schedule form is a long expression duplicated as a
  computation; promote it to a named computed signal so the
  `data-text="..."` becomes `data-text="$endsAt"`.
- **`data-indicator` on submit/cancel buttons.** Bind a signal that
  flips `true` while the request is in flight, then disable the button
  and show a spinner via `data-attr:disabled="$submitInFlight"`. Better
  than the current double-click vulnerability on `data-on:click`.
- **`data-on:event__document` modifier (new in 1.0.0).** Replace
  `data-on:keydown.escape.window="$showScheduleModal = false"` with the
  cleaner `data-on:keydown.escape__document` form for clarity.
- **`data-on-signal-patch`** (already in RC.7). Could let the list
  fragment react to specific signal changes without us hand-rendering
  full HTML on the server. Worth experimenting on the
  schedule-modal / history-modal toggle flow.

### 6.4 New features worth a feasibility look

- **`data-match-media` (Pro).** Bind a signal to a media query (e.g.
  `(max-width: 600px)`). Direct enabler for plan 04 §5.4 (mobile card
  layout): show the table on desktop, cards on mobile, with one signal.
  Note: this is a Datastar Pro attribute — confirm license model before
  adopting.
- **`@intl` action (Pro).** Internationalized formatting via the
  browser's `Intl` API. Could replace our `convertLocalTimes`
  MutationObserver in `base_shell.html.j2` for date/time formatting and
  remove ~15 lines of bespoke JS. Same Pro-license caveat.
- **`data-persist` (Pro).** Persist UI signals across reloads. Useful
  if we add user-level UI preferences (e.g. dismissed banners).
- **`attribute_generator` Python helper.** Type-checked `data-*`
  attribute construction with IDE completion. Has limited value inside
  Jinja templates, but **valuable in routes** when we build inline HTML
  fragments (the toast helper, stream-health patches). Worth adopting
  in the `routes/_html.py` module proposed in §5.1.
- **`read_signals(request)` (FastAPI helper in `datastar-py`).** Reads
  the JSON-encoded current signal state Datastar attaches to every
  request. Could simplify the schedule form (today we read individual
  `Form(...)` fields). Lower priority — current approach works.

### 6.5 Things we should leave alone

- The manual `MutationObserver` approach to local time conversion
  works; only swap it out as part of the `@intl` (Pro) decision.
- `data-signals:show-schedule-modal` on `<body>` is fine as global UI
  state for now.

## 7. Frontend / UX

- **7.A Asset caching.** `cache_bust = int(time.time())` on the field
  image regenerates per request, defeating browser cache. Use the
  file's `mtime` as the bust and add `Cache-Control: public, max-age=60`.
- **7.B Thumbnail caching.** `serve_field_thumb()` regenerates the JPEG
  on every request via Pillow. Cache to disk with mtime check, or
  pre-generate the thumb when the snapshot succeeds.
- **7.C Move inline CSS** from `base_shell.html.j2` to
  `static/style.css`; serve with long cache headers.
- **7.D `_list_all_content.html.j2` `colspan` magic** — drives column
  count from a constant; brittle. Use a single source of truth.

## 8. Observability

- **8.A Request-id middleware.** Add `X-Request-ID` and include it on
  every log line. Combined with the existing `error_id` returned by
  cancel/remove, this makes user-reported errors diagnosable.
- **8.B Prometheus metrics.** `prometheus-fastapi-instrumentator` plus
  custom gauges: active streams, scheduled jobs, snapshot age,
  ffmpeg restart count, login failures. Even without a Prometheus
  scraper, `GET /metrics` is useful for ad-hoc curl.
- **8.C Bound FFmpeg log retention.** Combines with plan 04 §6.4.
